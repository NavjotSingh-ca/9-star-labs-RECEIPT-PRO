### 2. ACCESSIBILITY (WCAG 2.1 AA)
**Test every interactive element:**

- **Color Contrast**:
  - Minimum 4.5:1 for normal text, 3:1 for large text (18pt+)
  - Check: text on bg-card, text on bg-champagne/*, text on bg-surface/*
  - Use automated axe-core + manual verification
  
- **Keyboard Navigation**:
  - Tab order logical and predictable
  - No keyboard traps
  - All interactive elements reachable via Tab (buttons, links, inputs, custom controls)
  - Visible focus indicator: 2px solid champagne, offset 2px
  - Custom widgets (dropdowns, modals, toggles) follow ARIA authoring practices
  
- **ARIA Attributes**:
  - All custom components have appropriate roles (dialog, menu, tabpanel, etc.)
  - aria-label where visible label absent (icon-only buttons)
  - aria-describedby for error messages
  - aria-expanded on toggle buttons
  - aria-live="polite" for dynamic content updates (toasts, live regions)
  - aria-sort on sortable table headers
  
- **Screen Reader Testing**:
  - Landmarks: header, nav, main, footer, complementary
  - Headings follow logical hierarchy (no skipped levels)
  - Form labels properly associated (htmlFor/id or aria-label)
  - Image alt text: descriptive or "" for decorative
  
- **Touch Targets**:
  - Minimum 44x44px for all touch controls
  - Adequate spacing between touch targets (8px minimum)
  
- **Motion & Animation**:
  - Respects `prefers-reduced-motion` - animation disabled or reduced
  - No flashing content (>3Hz or general flash threshold)
  - Animation duration reasonable (200-500ms for UI, 600-900ms for page transitions)
  
### 3. INTERACTION DESIGN & FEEDBACK

- **Button States**:
  - Default, hover, focus, active, disabled, loading
  - Clear visual feedback for each state
  - Disabled state has lower opacity (50%) and cursor: not-allowed
  - Loading state shows spinner or skeleton within button
  
- **Form Elements**:
  - Input: focus ring, valid/invalid states, error messaging
  - Select/menu: clear options, search/filter if >5 options
  - Checkbox/Radio: clear hit area, label clickable
  - Validation: inline, real-time where possible, prevent submission on error
  
- **Navigation**:
  - Consistent header/footer across pages
  - Mobile hamburger menu accessible and animates smoothly
  - Breadcrumbs where appropriate for deep navigation
  - Skip to main content link
  
- **Data Tables & Lists**:
  - Sortable columns with visual indicators
  - Selection modes clear (single/multi)
  - Bulk actions clear with selection count
  - Empty states: illustration, headline, primary CTA
  - Loading states: skeletons matching final layout, not spinners
  
- **Modals & Overlays**:
  - Background dimming and scroll locking
  - Escape key closes
  - Click outside to close (where appropriate)
  - Focus trapped within modal
  - Initial focus on first interactive element or dismiss button
  
- **Toasts & Notifications**:
  - Positioned consistently (bottom-right/top-right)
  - Auto-dismiss with pause on hover
  - Actionable toasts have clear buttons
  - Error toasts: distinct color, actionable if possible
  - Success toasts: brief, non-intrusive
  
### 4. PERFORMANCE & TECHNICAL UX

- **Rendering Performance**:
  - No layout thrashing (forced synchronous layouts)
  - Animations only animate transform and opacity
  - useLayoutEffect used only when DOM measurements needed
  - Expensive computations memoized (useMemo, useCallback)
  
- **Image Optimization**:
  - All images use next/image with proper width/height
  - Priority images (above-the-fold) have priority prop
  - Placeholders/blurred previews for LCP images
  - WebP/AVIF formats where supported
  
- **Bundle Impact**:
  - New imports justified and tree-shakable
  - No duplicate libraries (multiple chart libs lazy-loaded where appropriate
  - Critical CSS inlined, non-critical deferred
  
- **Server Components**:
  - Maximum use of Server Components where appropriate
  - Client components marked `'use client-only logic (For Next.js 16+) - maximize RSC usage, minimize client components
  - Data fetching in server components when possible
  - Client components only for interactivity, state, effects
  
### 5. MOBILE RESPONSIVE DESIGN

- **Breakpoints**: sm 640px, md 768px, lg 1024px, xl 1280px, 2xl 1536px
- **Navigation**:
  - Desktop: horizontal nav bar
  - Mobile: bottom tab nav or hamburger → drawer
  - Touch targets appropriately sized
  
- **Layout Adaptation**:
  - Grid columns: 1-col → 2-col → 3-col → 4-col as width increases
  - Cards stack vertically on mobile
  - Tables become scrollable or convert to cards
  
- **Typography Scaling**:
  - Fluid type or breakpoint-based scaling
  - Minimum 16px base font on mobile
  
- **Performance Considerations**:
  - Lazy load below-the-fold content
  - Optimize for cellular networks (progressive enhancement)
  - Minimize DOM nodes on mobile

### 8. MOTION & ANIMATION PRINCIPLES

- **Easing Standards**:
  - Enter: ease-out (cubic-bezier(0.23, 1, 0.32, 1))
  - Move: ease-in-out (cubic-bezier(0.645, 0.045, 0.355, 1))
  - Exit: ease-in (cubic-bezier(0.55, 0.085, 0.68, 0.53))
  - Hover: ease (cubic-bezier(0.25, 0.1, 0.25, 1))
  - Opacity only: linear
  
- **Duration Standards**:
  - Element enter/exit: 200ms
  - Element move: 200ms
  - Hover effects: 150ms
  - Page transitions: 600ms
  - Toast enter/exit: 300ms/200ms
  - Modal enter/exit: 300ms/200ms
  
- **Stagger Timing**:
  - List items: 50-100ms between items
  - Grid items: 50ms delay based on position
  - StaggerChildren in motion variants preferred
  
- **Performance**:
  - All animations use transform/opacity only (GPU accelerated)
  - Will-change: transform, opacity on animated elements
  - Respect prefers-reduced-motion (useReducedMotion hook)
  - No layout-affecting animations (height, width, top, left)
  
### 9. ERROR HANDLING & EDGE CASES

- **Network Errors**:
  - Clear, actionable messages
  - Retry options where appropriate
  - Offline indicators/caching where applicable
  
- **Validation Errors**:
  - Inline, real-time where possible
  - Field-specific, not generic form errors
  - Explain constraints (min/max, format, etc.)
  
- **Empty States**:
  - Never blank screens - always illustration + headline + CTA
  - Contextual based on user's current context/action
  
- **Loading States**:
  - Skeletons matching final layout shape
  - Progressive skeleton reveal (content appears as ready)
  - Skeleton shimmer animation for perceived performance
  
- **Edge Cases**:
  - Very long text (truncation with tooltip)
  - Very large numbers (abbreviation: 1.2K, 1.5M)
  - No data scenarios
  - Permission denied states (camera, location, notifications)

**Priority Levels**:
- **CRITICAL**: Blocks core functionality, accessibility violation, data loss/security risk
- **HIGH**: Significantly degrades UX, major usability issue, likely to cause user frustration/abandonment
- **MEDIUM**: Noticeable UX degradation, inconsistency, minor annoyance
- **LOW**: Polish issue, nitpick, minimal impact

**Impact Score** (1-10): 
- 9-10: Affects majority of users on core tasks
- 7-8: Affects significant user segment or frequent tasks
- 4-6: Affects minority or infrequent tasks
- 1-3: Minor polish, barely noticeable

**Related Principle**: Reference specific WCAG guideline (e.g., WCAG 1.4.3 Contrast Minimum) or UX heuristic (e.g., Nielsen's Visibility of system status)

**Special Instructions**:
1. Be brutally honest - don't soften issues for the sake of positivity
2. Include both what's wrong AND why it matters (user impact)
3. Suggest specific, actionable fixes (not just "make it better")
4. Group similar issues when they share root cause
5. For false positives (things that appear problematic but are correct by design), note as "INVESTIGATE" with explanation
6. Include positive findings where exemplary patterns exist (to preserve good practices)

**Output**: Start with a brief executive summary (3-5 bullet points) of top 3-5 critical issues, then the ranked table.
